# 注釈（マーカーとコメント）の設計

利用者の要望「論文にマーカー（ハイライト）やコメントを直接残したい」の設計です。実装は、この文書と §9 の判断の承認の後に行います。

---

## 1. 範囲

| 種類 | 内容 | 段階 1 |
| --- | --- | --- |
| マーカー | 選んだ文字に色を付ける。5 色（黄・緑・青・桃・紫）。既定は黄 | ○ |
| 下線 | 選んだ文字に色付きの下線 | ○ |
| コメント（マーカーに付ける） | マーカー・下線に文章を付ける。印の右端に小さな吹き出しを出す | ○ |
| 付箋 | 文字を選ばずに、ページの任意の位置に置くコメント | ○ |
| 取り消し線・手書き・図形 | — | ×（求められていない） |

**原文と訳文のどちらに付けるか**

訳文の PDF は、原文と同じページ数・同じ大きさで、各段落の訳文を原文の段落の場所に組んだものです（`core/render.py`）。
ただし訳文は、再翻訳・モデルの切り替え・ページ範囲の変更で文字の位置が変わり、同期では端末ごとに別の訳文を持つこともあります。
訳文の文字に直接付けた印は、そのたびに位置がずれるか、行き場を失います。

そこで、**注釈は原文に付ける**（位置は原文の PDF の座標で持つ）ことを基本にします。

- 原文の表示では、選んだ文字そのものに印を描く。
- 訳文の表示（「翻訳」「対訳」）では、同じページの同じ高さの左の余白に、同じ色の細い帯を描く。印のある段落の場所がわかり、帯にポインタを当てると引用とコメントを出す。
  訳文が変わっても、段落の場所は原文と同じなので、帯はずれない。
- 訳文の表示で文字を選んでマーカーを付けたいときは、段階 1 では「原文で付けてください」と案内し、原文の表示に切り替えて同じ場所を示す（§7 の段階 2 で、訳文への直接の印を検討する）。

## 2. データ

### 2.1 形

```jsonc
{
  "id": "<uuid4 の 16 進 32 桁>",
  "kind": "highlight" | "underline" | "note",       // note は付箋
  "page": 3,                                        // 0 始まり
  "quads": [[x0, y0, x1, y1], …],                   // 原文のページの座標（pt）。行ごとの矩形。付箋は位置の 1 点を [x, y, x, y]
  "quote": "選んだ文字（2,000 文字まで）",             // 一覧の表示と、書き出し・将来の位置の復元に使う
  "color": "yellow" | "green" | "blue" | "pink" | "purple",
  "comment": "コメント（10,000 文字まで。空ならなし）",
  "created_at": 1.8e9, "updated_at": 1.8e9
}
```

- 色は名前で持ち、表示の色はテーマ（明るい・暗い）で決める。PDF に書き出すときの色は固定の RGB を使う。
- 1 本の論文の注釈は 5,000 件まで（同期のファイルの大きさの上限 2 MB に収めるため）。

### 2.2 置き場所

| 案 | 内容 | 評価 |
| --- | --- | --- |
| **a. ライブラリの `state.sqlite3` の新しい表 `annotations`**（おすすめ） | ノートと同じく `CREATE TABLE IF NOT EXISTS`。DB の版は上げない | v0.3・v0.4.0 でもライブラリを開ける。検索・一覧が速い。バックアップ（`backup_to`）にも自然に入る |
| b. 論文ごとのファイル（`files/<id>/annotations.json`） | | 一覧・検索・同期の差分が面倒。書き込みの途中で落ちたときの扱いが要る |
| c. PDF の中に書き込む | 標準の PDF 注釈として保存 | **採らない**。PDF の中身が変わると sha256 が変わり、ライブラリと同期で「同じ論文」と分からなくなる。同期で PDF を毎回送り直すことにもなる |

NEXT.md §9 の判断 10「書き出しのときだけ PDF に書き込む」と同じ考え方で、**ライブラリの PDF は変えず、PDF 出力のときだけ書き込む**（§5）。

## 3. 同期

### 3.1 形式

ノートは state ファイルの 1 項目でしたが、注釈は件数が多く、1 件ずつ足し消しされるので、**論文ごとの別のファイル** `papers/<sha>/annotations.<端末>.json` に書きます。

```jsonc
{"kind": "annotations", "v": 1, "device": "<端末 ID>", "sha": "<sha256>",
 "items": {"<注釈の id>": {"body": {…§2.1 の id 以外…}, "hlc": "<HLC>", "alive": true}}}
```

- 端末は、自分が作った・変えた・消した注釈だけを書く（コレクションの所属と同じ形）。各注釈は `(alive, body)` を 1 つの値として HLC で比べ、新しい方を採る。
- 削除は `alive: false` の記録（tombstone）として残す。消した注釈がほかの端末から復活しない。tombstone は 90 日で書き出しから外す。
- 同期フォルダの `FORMAT` は 1 のまま。

### 3.2 同時の編集

| 起きること | 扱い |
| --- | --- |
| 2 台で別々の注釈を足す・変える | 両方残る（注釈ごとに id が違う） |
| 2 台で同じ注釈の色やコメントを変える | HLC の新しい方。コメントだけは、ノートと同じく、同時の変更を両方残して連結する（版ベクトル。`notes.py` を使い回す） |
| 片方が消し、もう片方がコメントを書く | HLC の新しい方（後で書いたコメントは残り、後で消したなら消える） |

### 3.3 古い端末との互換

- v0.3.0・v0.4.0 の同期は、`papers/<sha>/` の JSON を読み、知らない `kind` のファイルを `None` として無視する（コードで確認済み。`engine._parse`）。落ちず、壊さず、注釈のファイルを消さない。
- 古い端末は注釈を表示しないだけ。古い端末で論文を消したときは、注釈も新しい端末で（論文と一緒に）ゴミ箱に入る。
- 実装では、v0.4 の同期の互換と同じく、実物の v0.4.0 のコードでフォルダを読むことを手で確かめ、恒久のテストは「古い形のファイルが混ざっても壊れない」を足す。

## 4. 画面

### 4.1 付け方

```
読書画面のツールバー（左から）
 ‹ 3 / 15 ›   − 100% +   🔍   🖍▾   [原文|対訳|翻訳]   [翻訳]
                              └ マーカーの道具（押すと「付ける」状態、▾ で色と種類）
```

- **文字を選んでから付ける**（いつでも使える）: 原文で文字を選ぶと、選んだ範囲の上に小さな帯を出す。
  `[● ● ● ● ●]  [下線]  [コメント]  [コピー]`。色を押すとマーカー、コメントを押すとマーカーを付けてコメントの欄を開く。
- **マーカーの道具**（ツールバーの 🖍）を押している間は、文字を選んだらすぐに今の色のマーカーを付ける（続けて何か所も引くとき）。Esc で止める。
- **付箋**: マーカーの道具の ▾ から「付箋」を選び、ページの位置をクリックする。
- **キーボード**: ⌃⌘H（Windows・Linux は Ctrl+Alt+H）で選んだ文字に今の色のマーカー、⌃⌘N（Ctrl+Alt+N）でコメント付き。macOS のプレビューと同じ割り当て。

### 4.2 直す・消す

- 印をクリックすると、小さな吹き出しを出す: 色・種類の切り替え、コメントの編集（入力をやめて 1 秒後に保存）、削除（取り消せるよう、帯に「元に戻す」を 5 秒出す）。
- 選んで Delete キーでも消せる。

### 4.3 右のパネルの「注釈」タブ

右のパネルに 4 つ目のタブ「注釈」を足す（論文の詳細・AI 翻訳の詳細・ノート・**注釈**）。

- 一覧: ページ順に、色の印・ページ番号・引用（2 行まで）・コメント（3 行まで）。クリックでその場所へ移り、印を一時的に強調する。
- 上に、色での絞り込みと「コメントのあるものだけ」。件数を出す。
- 注釈がない論文では、付け方の案内を出す。
- ライブラリ画面の詳細パネルにも同じタブを出す（読書画面を開かずに見直せる）。

## 5. PDF 出力への反映

PDF 出力のダイアログに「注釈を含める」（既定はオン）を足す。含めるときは、**標準の PDF 注釈**で書く（ほかの PDF ビューアでも表示・編集できる）。

| 出力の形式 | 書き方 |
| --- | --- |
| 原文（そのまま） | 原文のページに、マーカーは Highlight、下線は Underline、付箋は Text（コメントを中身に）。コメント付きのマーカーは、注釈の中身にコメントを入れる |
| 対訳（左右に並べる） | 左（原文）の部分に、座標を合わせて同じく書く |
| 対訳（交互） | 原文のページに書く |
| 翻訳のみ | 訳文のページの左の余白に、同じ色の細い帯（Square 注釈）と、コメントがあれば付箋。帯の中身に引用とコメント |

書き込むのは出力したファイルだけで、ライブラリの PDF は変えない。PyMuPDF の `add_highlight_annot` などを使う（追加の依存はない）。

## 8. セキュリティとプライバシー

- 注釈は、同期を有効にしたときだけ同期フォルダに書く（書誌情報・ノートと同じ扱い）。翻訳サービスには送らない。
- ほかの端末から来た注釈は外部入力として検証する（型・長さ・座標が有限でページの中・色は決まった名前だけ・件数の上限・`clean_text` で見えない文字を除く）。
- SECURITY.md の「同期するもの」に注釈を足す（e8）。
